# Implementation roadmap

Each milestone ends with reviewable evidence. All commands, schemas and dependency pins in this repository are design proposals until their milestone passes. A failed capability gate narrows the advertised capability; it never authorizes modifying the Steam client.

| Milestone and dependencies | Deliverable | Acceptance and risk gate |
|---|---|---|
| 1. Windows feasibility, no dependencies | Minimal locked native window, synthetic library, one command-mode entry, offline Windows CI and portable staging directory. Record OS/GPU/toolchain/DLL graph. | On clean Windows 11 x64 as standard user, launch from a path containing spaces; tab through search, open/dismiss a menu, edit Unicode text, expand/select virtual rows and inspect UIA/Narrator. Command mode exits without a window. Record output size, startup and idle measurements against [UI budgets](../.agents/standards/ui.md). Compare Base-only with selective Component before choosing production features. Document any redistributables or fallback ZIP. |
| 2. Steam read-only compatibility, after foundation | Fake Steam roots, profile chooser, lossless shortcut reader, native manifest index, collision report and read-only dry-run. | Multiple profiles, unknown supported fields, Unicode paths and ID conversion vectors round-trip. Malformed or unsupported data blocks apply. Hand-created shortcuts survive byte-for-byte. Isolated client experiment confirms ID and art conventions. No dependency on a real store. |
| 3. Store discovery, after headless core | Epic local discovery first, GOG next; independent mock account snapshots, credentials and capability matrix. | Each connector passes offline installed-only, owned-uninstalled, pagination failure and disconnect fixtures. Before offering account sync demonstrate a permitted client identity, browser flow, refresh and scoped coverage with consented test data; otherwise ship local-only. First-run inventory usable without network. |
| 4. Duplicate reconciliation, after observations and profile discovery | SQLite identities, confidence/provenance, negative mappings, native avoidance, store ranking, per-profile preview, durable merge/split undo. | Run every [duplicate fixture](../.agents/testing/duplicate-fixtures.md), shuffled and repeated. Check for zero weak automatic matches, retained entitlements and stable binding IDs. Review where a provider collapses editions. No Steam writes needed. |
| 5. Dispatcher and recovery, after read-only compatibility and selection | Disposable profile write spike, stable path/token, typed launch/install intents, journal, backup, safe removal and restore. | Power-loss simulation after each file/DB step converges or presents a conflict. Concurrent Steam and stale plans cannot silently overwrite a changed file. Confirm stable IDs after switching store/installation and after update or relocation repair. Record direct-child vs URI handoff results for Input, overlay and lifetime. Block publication without a validated action. |
| 6. End-to-end sync and artwork, after dispatcher and recovery | Full Library → preview → apply → verify workflow; optional per-user SteamGridDB and local asset overrides. | Second sync writes zero files, changing art touches only approved slots, auth/throttling/invalid images leave game sync available. Confirm five slots on a disposable client, preserve manual edits, restore after interrupted sync. |
| 7. Optional native collections, after writer | Version-tested static collection adapter, editable names, install/unknown membership changes. | Test Steam closed, restart, cloud reconnect, second-client divergence and manual edits. Unrecognized namespace or client behavior leaves membership pending. Ship shortcuts independently if cloud test fails. |
| 8. Xbox and wider release, after store contract | Installed-package-only Xbox first; expose further capabilities only with evidence. Consider other stores one capability at a time. Release package, accessibility/performance results and recovery/support guides. | Confirm at least one supported local Xbox package model and honest handling of unsupported installs. Do not label activity as ownership. Test upgrade, missing launcher, offline use, cache cap, relocation and uninstall without deleting user assets. Recheck upstream API terms, project license, name and notices before distribution. |

The project uses the [MIT License](../LICENSE). The maintainer still needs to confirm public branding before launch. Engineering owns the experiments and dependency choices. No decision on a paid metadata backend, standing service or Steam login is required for the local-first milestones.
