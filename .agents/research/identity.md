# Identity evidence and its limits

**Source-verified • Local Steam discovery.** In steamlocate (MIT), Windows `locate_steam_dir_helper` reads machine InstallPath in two registry locations. The library reader enumerates roots from `steamapps/libraryfolders.vdf`. `Library::from_dir` scans each root's steamapps for numeric `appmanifest_*.acf` because cached folder entries may be stale. `Library::app` opens the corresponding manifest and `resolve_app_dir` resolves the install directory. This supplies a Rust read adapter worth evaluating against the project's fixtures. Validate internal AppID, installation state and on-disk path, distinguish unavailable drives, and keep the account inference separate. Cached appinfo may enrich a label; title metadata alone cannot confirm any purchase. A typed reader that exposes only known fields still needs separate lossless-writer validation. [Library reader](https://github.com/WilliamVenner/steamlocate-rs/blob/d740b423aee82e8e742595d0cdb4edcc91c24216/src/library.rs) · [Windows lookup](https://github.com/WilliamVenner/steamlocate-rs/blob/d740b423aee82e8e742595d0cdb4edcc91c24216/src/locate/windows.rs)

**Source-verified • Steam ROM Manager.** FileParser runs fuzzy title matching after parser/custom-variable extraction. Its final userExceptionsPromise stage checks exclusions and applies matching exceptions, including title, argument, compatibility-tool and artwork search overrides. SRM separates its artwork search query from the title used in a shortcut. Adopt that distinction and the ability to correct a result; its configurable title pipeline does not verify cross-store licensing or edition equivalence. The reviewed SRM tree carries GPLv3. Use as behavioral evidence unless reuse is separately approved under a compatible project license. [Parser and exceptions](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/file-parser.ts) · [License](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/LICENSE)

Source review on 2026-11-21. Verified describes code or provider documentation. Inferences describe expected consequences. Product policy is in the [matching contract](../architecture/game-identity-and-duplicates.md).

**Verified • Playnite.** A library item has a database identity, plugin GameId and PluginId, SourceId, Version and IsInstalled. Custom entries can have a generated game ID. Two plugin items need not share any identifier across catalogs. A mutable display name is a poor join key. See Game constructor and field comparisons. [Game.cs, 8c08a30](https://github.com/JosefNemec/Playnite/blob/8c08a305d68e287e71984ea691239212a6046cf7/source/PlayniteSDK/Models/Game.cs)

**Verified • DuplicateHider and DuplicateHiderNG.** In both implementations GetFilteredName uses a custom group's GUID when present and a filtered display name otherwise. GetGameFilter takes account of platform, source, categories and ignored items, and includes explicit group members. GameComparer.Compare resolves manual group order when enabled, then priority tags and configured comparison properties. The NG branch handles null names, caches priority-tag sets, and can bypass platform filtering. ResolveGroupConflicts handles assigning a game already in a different custom group. This is a preference ordering *after* a grouping decision. A high preferred-store rank cannot prove two products are equivalent. Both checkouts carry MIT licenses. Adopt user correction, exclusions and separate ranking. Name buckets are useful candidate generators only. [Original algorithm, bd8008a](https://github.com/felixkmh/DuplicateHider/blob/bd8008ae36af569efb1c3482bd1e359107685555/source/DuplicateHiderPlugin.cs) · [NG algorithm, e1f3e50](https://github.com/gOOvER/Playnite-DuplicateHiderNG/blob/e1f3e500f420fe63d43a4025e49dafedbbf67449/source/DuplicateHiderPlugin.cs)

**Verified • IGDB.** The external_games table joins provider-specific identifiers to games. Game records distinguish version_parent/version_title, remakes, remasters, standalone expansions and bundle relationships. A parent link explains relatedness, not interchangeability. Check source namespace, PC platform and version scope on both sides. The API requires a Twitch application client ID and app access token. The documented ceiling is four requests/sec and eight open requests. Local caching is encouraged. Commercial integration requires checking partnership and attribution terms. None of this licenses unrestricted redistribution of a catalog dump. For an offline-first public executable defer an integrated IGDB service until there is a legitimate credential model. Never embed a shared client secret. [API schema, access, terms and limits](https://api-docs.igdb.com/)

**Inferred • SteamGridDB.** Platform ID lookup can resolve a store product to the art provider's game entry without Steam login. An art entry can serve several releases. Even two successful lookups to the same entry need release-level corroboration. Persist manual art corrections separately from identity overrides. Use bounded requests, retry/backoff and per-user credentials as described in [Steam and artwork research](steam.md).

**Verified • Steam inventory.** Local installations and shortcuts provide evidence with different scopes. A machine-wide install does not establish a purchase by a specific account. GetOwnedGames is a keyed network API with visibility restrictions. It cannot supply the unconditional, private, unauthenticated inventory a default import would need. Accept explicit, locally entered AppIDs/exclusions as additional user evidence. Keep manually supplied IDs distinguishable from a detected native install. [Valve IPlayerService](https://partner.steamgames.com/doc/webapi/IPlayerService) · [Steam files and exceptions](steam.md)

**Proposed minimum.** Ship offline overrides plus a small, reviewable mapping table only if every mapping has distributable provenance, platform, release and product kind. Provider outages degrade to existing decisions and separate rows. Never send an account ID or a full owned library to a metadata service merely to compare two names. Require opt-in before external enrichment. Unresolved: measure edition-level coverage on a consented, labeled sample, including negative pairs. Report false merges separately from missed duplicates. Exclude a provider from automatic matching until precision is demonstrated on those negative pairs.
