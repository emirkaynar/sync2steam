# GPUI stack and Windows feasibility

Research snapshot for 2026-11-21. Version evidence comes from published manifests and upstream documentation. Sync2Steam has no desktop build or benchmark results at this stage.

## Candidate stacks

| Stack | What it supplies | Compatibility evidence |
| --- | --- | --- |
| Zed GPUI | Zed Industries’ Rust UI runtime, rendering, entities, windows, actions, and primitive elements | Zed’s official `gpui` crates.io package is at `0.2.2`. The Zed repository and its current native-platform crates are a separate source option. Source builds need all GPUI crates from the same revision. [Official package](https://docs.rs/crate/gpui/0.2.2) · [Zed source](https://github.com/zed-industries/zed/tree/main/crates/gpui) |
| Longbridge GPUI Kit | `gpui-kit` facade, GPUI Base, styled GPUI Component, and embedded default icons | Kit `0.10.0` was released 2026-11-16. The published manifest requires `gpui-pre`, `gpui-pre-platform`, and `gpui-pre-macros` exactly `0.3.12`, with Base, Component, and Kit assets on the `0.10.0` dependency family. `gpui-pre 0.3.12` publishes a snapshot from Zed revision `d2a4fb6`. [Release](https://github.com/longbridge/gpui-kit/releases/tag/v0.10.0) · [Kit manifest](https://docs.rs/crate/gpui-kit/0.10.0/source/Cargo.toml) · [Snapshot metadata](https://docs.rs/crate/gpui-pre/0.3.12) |

[Base](https://gpui-kit.com/base/) · [Component catalog](https://gpui-kit.com/component/) · [Kit FAQ](https://gpui-kit.com/docs/faq/) |

[CE runtime](https://github.com/gpui-ce/gpui-ce) · [CE component manifest](https://github.com/gpui-ce/gpui-component/blob/main/Cargo.toml) · [Runtime `0.3.0`](https://docs.rs/crate/gpui-ce/0.3.0) |

## Recommended feature profile

Start with `gpui-kit = "=0.10.0"` and a committed `Cargo.lock`. Use the styled `DataTable`, search `Input`, menus, and form controls selectively. Their common focus behavior, theme, state affordances, and reusable table support address the work required by all four screens. Keep the application shell, grouping, data projection, and row details in Sync2Steam. Use Base primitives where the product needs its own presentation. This keeps the UI original and avoids building a complete behavior and styling layer for routine controls. The catalog is one `component` feature, so selective imports are a source-code choice and do not reduce the dependency graph widget by widget. Measure the release executable and startup before deciding whether the cost warrants a Base-only design. [Component source and initialization](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/src/lib.rs) · [Kit feature manifest](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/kit/Cargo.toml)

| Profile | Cargo requirement | Windows dependency edges verified in the release manifests |
| --- | --- | --- |
| Base only | `gpui-kit = { version = "=0.10.0", default-features = false }` | Kit depends on `gpui-base`, `gpui-pre`, `gpui-pre-macros`, and `gpui-pre-platform`. Base depends on the same core and macros, plus `gpui-pre-sum-tree`, text/editing libraries such as `ropey`, `lsp-types`, Markdown and HTML parsers, and Windows support for the system reduced-motion preference. The native platform keeps its manifest features, including `runtime_shaders`. Neither styled Component nor Kit assets are activated by this profile alone. |
| Base and styled components with explicit asset handling | `gpui-kit = { version = "=0.10.0", default-features = false, features = ["component"] }` | Component adds `gpui-component-macros` and depends on `gpui-kit-assets` itself. This profile still pulls in the assets package transitively. The facade’s `gpui_kit::assets` export remains disabled. |
| Recommended default | `gpui-kit = "=0.10.0"` | Kit activates `component` and `assets`, exposing the asset source directly for `.with_assets(...)`. Speech, Tree-sitter grammars, Syntect, and GPUI Fast are opt-in. |

These are feature edges from the manifests. Confirm the resolved versions and feature unification on Windows with `cargo tree --locked --target x86_64-pc-windows-msvc -e features` and `cargo tree --locked --target x86_64-pc-windows-msvc -d`. Import GPUI through the facade to keep one runtime type identity. Treat GPUI Fast as a measured follow-up if the default misses an agreed budget. Keep the optional JavaScript shell and WebView outside the desktop scope. In test builds, Kit’s `test-support` forwards to GPUI, its platform, and Base, and to Component if enabled. For a Base-only spike, keep `default-features = false` on the development dependency too. [Workspace manifest](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/Cargo.toml) · [Kit manifest](https://docs.rs/crate/gpui-kit/0.10.0/source/Cargo.toml) · [Base manifest](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/base/Cargo.toml) · [Component manifest](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/Cargo.toml) · [Cargo tree](https://doc.rust-lang.org/cargo/commands/cargo-tree.html)

## Released source and maintenance evidence

- **Bootstrap and overlays.** In `crates/kit/src/lib.rs`, `application` re-exports the native platform entry point, `open_window` wraps the supplied content entity in `base::Root::new`, and `init` selects Base or Component initialization by feature. Base’s `root.rs` implements Tab traversal with focus containment and provides `Root::register_plugin`. Component’s `root.rs` registers `WindowState` through that hook and holds styled dialogs, sheets, notifications, tooltips, and focus restoration state. Base-only applications supply their overlay presentation around the Base primitives. [Kit facade](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/kit/src/lib.rs#L165) · [Base Root](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/base/src/root.rs#L38) · [Component Root plugin](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/src/root.rs#L19)
- **Text editing.** Base’s `input/mod.rs` exports single-line `Input` and `InputState`, alongside `Textarea` and `Editor` and their states. It assembles native input, selection, accessible text, movement, masking, and undo modules. Component’s `input/mod.rs` re-exports Base’s state and actions and provides styled wrappers. Use a long-lived `InputState::new` with `Input::new` for Library search and verify caret, clipboard, undo, selection, and IME composition in a real Windows session. Base-only presentation requires styling the field, cursor, selection, focus, and context-menu affordances. [Base input source](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/base/src/input/mod.rs) · [Component input source](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/src/input/mod.rs) · [Base Input guide](https://gpui-kit.com/base/primitives/input/)
- **Menus and popovers.** Component’s `lib.rs` exposes `menu`, `native_menu`, and `popover` and initializes the styled menu and popover systems. Use `PopupMenu` with `ContextMenuExt` or a dropdown trigger for commands routed through GPUI Actions. Use `Popover::new` for anchored contextual content. Base offers a controlled `Popover::new` when the app needs to own the trigger and panel styling. The Component manifest separately enables Win32 APIs for native popup menus. Verify keyboard invocation, dismissal, focus return, and screen-reader actions before relying on any Windows-native menu variant. [Component module exports](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/src/lib.rs) · [Menu guide](https://gpui-kit.com/component/menu/) · [Component Popover](https://gpui-kit.com/component/popover/) · [Base Popover](https://gpui-kit.com/base/primitives/popover/) · [Native menu dependencies](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/Cargo.toml#L237)
- **Theme and tokens.** Component’s `theme/mod.rs` re-exports Base’s `SemanticThemeTokens`, `ColorTokens`, `SpacingTokens`, `RadiusTokens`, and `TypographyTokens`. `Theme::sync_system_appearance` reads window or app appearance. `Theme::update` refreshes windows and projects shared tokens and control settings down to Base. Define Sync2Steam’s visual tokens once and map them through this theme so custom rows and toolkit controls agree. Evaluate Windows contrast themes and text scaling independently in the spike. [Theme source](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/src/theme/mod.rs)
- **Table delegate.** The shipped `TableDelegate` exposes `render_tr`, `render_td`, `cell_label`, `row_label`, `context_menu`, and `visible_rows_changed`. The default `render_tr` uses the row index for its element ID, so use a domain-derived key for grouped rows that move during sorting and filtering. `cell_label` defaults to empty. Supply the meaningful visual fields and group states through the semantic tree and verify them with UIA. [Table delegate source](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/component/src/table/delegate.rs)
- **Licensing and upgrade cadence.** Longbridge’s released Kit, Base, Component, and asset package manifests declare Apache-2.0. Zed publishes GPUI’s license in the GPUI subtree, and Longbridge states that its `gpui-pre` snapshots preserve upstream notices. Inventory actual packaged dependencies, icons, and fonts and carry their applicable notices. The November 2, 9, and 16 Kit releases show active upstream updates, including changes to public theme and text input APIs. Longbridge’s tagged workspace records a previous compilation failure after automatic GPUI snapshot drift and documents its exact-pin CI check. Keep release tags and the lock file together, then rerun Windows rendering, focus, UIA, and packaging smoke tests on upgrades. [Longbridge license](https://github.com/longbridge/gpui-kit/blob/v0.10.0/LICENSE-APACHE) · [Asset manifest](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/crates/assets/Cargo.toml) · [Zed GPUI license](https://github.com/zed-industries/zed/blob/main/crates/gpui/LICENSE-APACHE) · [Snapshot FAQ](https://gpui-kit.com/docs/faq/) · [Release history](https://gpui-kit.com/releases/) · [Workspace pin rationale](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.10.0/Cargo.toml#L58)

## Primitives to prove with the Sync2Steam spike

| Need | Candidate and verification |
| --- | --- |
| Window and navigation | Initialize Kit once, register default assets, then open the single main window with the Kit `Root` wrapper. Use the styled Sidebar for top-level navigation and verify its selected state and keyboard focus. Root hosts dialogs, sheets, and notifications. Keep system window decorations for the initial build. [Getting Started](https://gpui-kit.com/docs/getting-started/) · [Root](https://gpui-kit.com/component/root/) · [Sidebar](https://gpui-kit.com/component/sidebar/) |
| Library and preview | Evaluate `DataTable` with a virtualized fixed-height row projection for grouped titles and expanded source rows, or a Base/Component virtual list for variable-height detail. Keep title and copy identity in the model, independent of generated row index. The table delegate needs explicit cell labels for screen readers. Verify stable focus through filtering, re-sorting, expanding, and scrolling off-screen. [DataTable](https://gpui-kit.com/component/data-table/#accessibility) · [VirtualList](https://gpui-kit.com/component/virtual-list/) |
| Controls and feedback | Prefer styled inputs, checkboxes, selects, buttons, progress, and alerts. Inspect busy, empty, error, mixed, disabled, and keyboard-focus states with the actual theme. Use Base when the product needs a missing presentation while retaining reusable interaction and semantics. [Component catalog](https://gpui-kit.com/component/) · [Accessibility](https://gpui-kit.com/docs/accessibility/) |
| Key routing | Register named actions and scoped keybindings. Retain focus handles with the owning view, track them on rendered elements, and restore focus when a dialog closes. Exercise keyboard, pointer, and assistive activation against the same app command once per input. [Keybinding](https://gpui-kit.com/docs/keybinding/) · [Focus](https://gpui-kit.com/docs/focus/) |
| Accessibility and automation | AccessKit is wired into the framework. Custom nodes need a stable element ID, meaningful role, name, relevant state, and an activation path. The documented `accessibility_id(...)` maps to Windows UIA AutomationId. Verify the real control tree, events, and action patterns in Windows, including virtualized rows and disabled actions. [GPUI Kit accessibility](https://gpui-kit.com/docs/accessibility/) · [Accessibility Insights Inspect](https://accessibilityinsights.io/docs/windows/getstarted/inspect/) |

## Windows development and distribution

- Start with the Windows x64 MSVC target, Visual Studio 2022 Build Tools with Desktop development with C++ and Windows SDK, and CMake in `PATH`. Kit documents Windows 10 or later and recommends Rust 1.92 or later for its current locked graph. Pin the toolchain that builds the selected application lock. Confirm the supported Windows builds and GPUs for Sync2Steam on actual systems. Zed’s DirectX 11 and vendor GPU driver requirements describe Zed and inform the device matrix. [Kit installation](https://gpui-kit.com/docs/installation/) · [Zed Windows requirements](https://zed.dev/docs/installation#windows)
- Build a locked release package and stage its exact runtime contents. A portable ZIP is the simplest first distribution candidate. An Inno Setup installer is a candidate when Start-menu registration and uninstall matter. Sign the executable first and verify it after staging. If shipping an installer, sign setup and its uninstaller through the supported workflow. Verify DLL and resource requirements, icon and DPI behavior, app identity, shortcut and protocol behavior used by the product, and launch from a clean VM as a standard user without development tools. Exercise upgrade and uninstall with test user data outside the install directory. Recheck an Arm64 artifact on its own target if offered. [Kit desktop packaging](https://gpui-kit.com/docs/packaging/#windows) · [Microsoft distribution options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/choose-distribution-path)
- Use Rust unit tests for pure behavior, then Kit `test-support` with the same pinned dependency for entities, actions, async, focus, layout, and semantics. Windows runs the portable interaction suite. Kit’s offscreen renderer explicitly skips Windows pixel checks with the pinned platform. Run screenshot and render verification on a foreground Windows session with a working GPU plus native UIA inspection and Narrator passes. Include packaged first launch, multi-monitor DPI changes, scale, reduced motion, contrast themes, keyboard layouts, and window lifecycle. [Kit testing](https://gpui-kit.com/docs/test/) · [Microsoft accessibility practices](https://learn.microsoft.com/en-us/windows/apps/get-started/best-practices#accessibility-testing)

The spike should produce a locked Windows release build, a working virtualized library with grouped row expansion, evidence of keyboard and Narrator operation, and the benchmark captures defined in the [UI standards](../standards/ui.md). Use those results to accept the dependency pin and Windows support baseline.
