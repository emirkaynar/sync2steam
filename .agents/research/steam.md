# Steam client integration research

Reviewed 2026-11-21 for Windows 11. **Documented** means Valve, Microsoft, or SteamGridDB publishes the behavior. **Source-verified** means the named upstream revision implements it. Steam’s disk formats and process behavior still require client validation. This review used public sources and accessed no local Steam installation, account, or API key. The proposed implementation is in [Steam and artwork](../architecture/steam-and-artwork.md).

## Supported Steam behavior and discovery

Valve supports adding a local non-Steam shortcut via the client’s Games menu. Adding one does not confer Steam ownership or Steam-distributed updates. The client support page does not document bulk import, a shortcut-write API, or the underlying file contract. Treat automation of the private files below as a compatibility adapter. [Valve non-Steam shortcuts](https://help.steampowered.com/en/faqs/view/4B8B-9697-2338-40EC)

Windows discovery sources support candidates at `HKCU\Software\Valve\Steam` value `SteamPath`, and `HKLM\SOFTWARE\Valve\Steam` value `InstallPath` using explicit registry views, particularly the 32-bit view on 64-bit Windows. Valve acknowledges the machine key under `Wow6432Node` and the default installation at `C:\Program Files (x86)\Steam`. Discovery precedence, validation and an explicit path picker are project decisions. Additional `steamapps` library roots may contain installed titles, while shortcut writes target the selected client’s `userdata`. [Windows registry discovery reference](https://github.com/osztenkurden/steam-game-path/blob/master/docs/windows-registry.md) · [Valve uninstall documentation](https://help.steampowered.com/en/faqs/view/3C73-90F9-F600-0266) · [Valve launch options](https://help.steampowered.com/en/faqs/view/0188-6BB7-D467-08E1)

SRM’s `getAvailableLogins` reads the text VDF at `config/loginusers.vdf`, iterates its SteamID64 keys and supplements them by enumerating numeric `userdata` directories other than `0`. `steamID_64_ToAccountID` subtracts `0x0110000100000000` for normal individual accounts. Treat the result as a profile candidate and verify the matching numeric directory. A cached login, recent timestamp or orphan profile is insufficient authorization for a write. Use integer or decimal-string arithmetic for SteamID64. [SRM login enumeration](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/helpers/steam/get-available-logins.ts#L9-L78) · [SRM account conversion](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/helpers/steam/steam-id-64-to-account-id.ts)

## SRM save path and shortcut format

The inspected SRM tree is commit `a02608984941eea9361afbc4a7b1fe2a162845e8`. Release 2.6.3 separately documents wrapper-related ID changes, non-SRM icons and launcher lifetime behavior. The paths below are relative to the selected client’s `userdata/<accountId>/`.

| File or directory | Source-verified role |
| --- | --- |
| `config/shortcuts.vdf` | Per-profile binary shortcut records |
| `config/grid/` | Per-profile artwork overrides and optional logo layout |
| `config/addedItemsV2.json` | SRM’s own ledger of imported IDs, parser ownership, artwork-only status and categories |
| `760/screenshots.vdf` | SRM also writes `shortcutnames` metadata here. Client necessity for Sync2Steam’s MVP remains unverified |
| `config/cloudstorage/` | Local Steam cloud-storage namespace JSON used by SRM for collections |

The path constructors use `generateListFromPreviewData` and `generateListFromDirectoryList`. `VDF_Manager.mergeData` tracks ownership and prunes stale entries by parser, then writes artwork, shortcut and ledger data through distinct writers. SRM makes an overwriteable `.backup` and an initial `.firstbackup` for shortcuts and screenshots. `VDF_ShortcutsFile.write` calls `fs.outputFile` on the destination and collections use a direct write. This provides concrete interoperability evidence and illustrates the need for an independent multi-file recovery protocol. [SRM file paths](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/helpers/vdf/generate-list-from-directory-list.ts#L32-L61) · [SRM ownership ledger](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-added-items-file.ts) · [SRM manager](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-manager.ts#L105-L461) · [SRM shortcut writer](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-shortcuts-file.ts#L123-L163)

**Binary VDF.** SRM delegates to `steam-shortcut-editor` 3.1.3. Its codec uses nested objects (`0x00`), UTF-8 NUL-terminated keys and string values (`0x01`), little-endian signed 32-bit values (`0x02`), and object terminators (`0x08`). The root field is `shortcuts` with numeric record keys. Per-record fields include `appid`, `AppName`/`appname`, `Exe`/`exe`, `StartDir`, `LaunchOptions`, `icon`, plus nested numeric-key `tags`. Existing entries can carry `LastPlayTime`, `IsHidden`, `AllowOverlay`, `sortas` and other metadata. SRM normalizes a set of key aliases and can find a renamed or foreign record by its stored ID. Its dependency converts some values to JS booleans/arrays and models keys as object properties, so duplicate keys, unsupported wire types and exact byte preservation require separate handling. [SRM reader and stored-ID lookup](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-shortcuts-file.ts#L46-L179) · [Parser](https://github.com/tirish/steam-shortcut-editor/blob/d755f03e28280e64c96e4a6039739fcb41e28f0e/lib/parser.js) · [Wire tags](https://github.com/tirish/steam-shortcut-editor/blob/d755f03e28280e64c96e4a6039739fcb41e28f0e/lib/constants.js)

**IDs.** SRM hashes the literal executable field concatenated with the name using IEEE CRC-32 over UTF-8. The executable string includes whatever quotes are present in that field. Preserve all 32 bits and force the high bit with `0x80000000`. Serialize the resulting bits to VDF as a signed little-endian int32. Use the unsigned decimal representation for artwork and collection records. Its 64-bit decimal shortcut game ID is `(uint64(shortId) << 32) | 0x02000000`, used by SRM as its internal key and as a legacy horizontal art alias. Use exact arithmetic. The existing VDF `appid` can differ from a new hash after renaming or when another importer assigned it. Read the stored bits for existing objects. Hash-derived IDs are collision-prone by design and are unsuitable as application ownership keys. [SRM ID helpers](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/helpers/steam/generate-app-id.ts) · [SRM CRC implementation](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/helpers/steam/crc32.ts)

## Collections and local cloud storage

`CategoryManager.doCatTask` reads `config/cloudstorage/cloud-storage-namespaces.json` as namespace/version pairs. At the pinned revision, it looks for a namespace file containing `user-collections.` and defaults to namespace 1 when it finds none. Namespace version numbers are independent. Choosing the numerically largest version can pick an unrelated namespace. The code reads `cloud-storage-namespace-<id>.json` as an array of key/value envelopes. Collection key `user-collections.<id>` maps to an envelope whose `value` is an encoded JSON object containing `id`, `name`, `added` and `removed`. The code skips tombstones (`is_deleted`), writes Unix-second timestamps and string versions, and writes `conflictResolutionMethod: "custom"` and `strMethodId: "union-collections"` on new or replaced rows. These are direct observations of SRM’s convention. Valve’s acceptance and merge rules are unverified. [SRM namespace discovery and envelope merge](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/category-manager.ts#L28-L276)

`writeCat` resolves matching collection names case-insensitively, creates `srm-` plus base64url of the name when absent, and merges unsigned short IDs. The SRM ledger also lets it remove former memberships on subsequent saves and tombstone unused SRM collections. SRM unions categories into shortcut `tags` separately. Tags are useful metadata but do not establish that modern library collections appear after reload. The actual `doCatTask` writes only when a namespace file exists. Comments mention a `localconfig.vdf` cache/fallback, while the inspected method contains no fallback write. Older Steam/SRM approaches involving the local cache or web-helper LevelDB should not be treated as the current path. Verify offline startup, restart persistence and later online reconciliation independently. [SRM writeCat](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/category-manager.ts#L278-L475) · [SRM tag update](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-manager.ts#L394-L441)

## Client lifecycle and dispatch references

- SRM’s `performSteamlessTask` optionally stops the client, runs the save and restarts only if it stopped Steam. Its Windows helper launches `steam.exe -shutdown` via PowerShell from a hardcoded default install, checks the process repeatedly and delays after exit. Use the chosen installation path for any equivalent action and treat restart as a separate result from file commit. [SRM lifecycle helpers](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/helpers/steam/stop-start-steam.ts#L76-L184)
- SRM 2.6.3’s launch wrapper can run the target plus pre/post scripts and tries to keep Steam tracking a game when a launcher hands off. Its release notes say enabling/disabling the wrapper changes IDs. This is evidence for testing lifetime and explicit migrations. It does not establish what Steam will do with every process model. [SRM wrapper source](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/launch-wrapper/index.ts) · [SRM 2.6.3 notes](https://github.com/SteamGridDB/steam-rom-manager/releases/tag/v2.6.3)
- SteamAll at `6f1d2579e0fbb1e87afa955316d7686e3244a60b` documents preview/apply, preserving shortcut IDs, BoilR adoption, cached art and a separate Windows launcher. Its launcher creates the child and waits on its process handle. Its README explains a store-opening shortcut shows **Play** in unmodified Steam. The **Install** UI and install-state changes depend on its Millennium plugin. SteamAll is useful as an independent design reference. [SteamAll README](https://github.com/Koisuji02/SteamAll/blob/6f1d2579e0fbb1e87afa955316d7686e3244a60b/README.md) · [SteamAll Windows launcher](https://github.com/Koisuji02/SteamAll/blob/6f1d2579e0fbb1e87afa955316d7686e3244a60b/src/SteamAll.Launcher/Program.cs#L28-L115) · [BoilR](https://github.com/PhilipK/BoilR)

**Client validation pending.** Establish the supported client build/offline state, ID stability after rename and executable changes, acceptance of distinct IDs for identical name and target with different launch tokens, overlay and Steam Input for direct versus wrapped or URI-launched games, play-time/lifetime tracking, desktop and Big Picture visibility, restart requirements and scaling. No documented Steam shortcut count or Steam-specific launch-option length limit was found. Win32’s `CreateProcessW` command-line ceiling of 32,767 characters including NUL is an OS bound only. ## Artwork placement and SteamGridDB

SRM uses the following stems under `userdata/<accountId>/config/grid/`. Extensions must correspond to the accepted image bytes. SteamGridDB IDs belong to its catalog and never enter these filenames.

| Asset | Stem using unsigned decimal `shortId` |
| --- | --- |
| Portrait grid | `<shortId>p` |
| Landscape grid | `<shortId>`; SRM also creates `<gameId64>` using the same file contents |
| Hero | `<shortId>_hero` |
| Logo | `<shortId>_logo` |
| Icon | `<shortId>_icon`; set shortcut `icon` to the installed local path |

For the landscape alias SRM attempts a link and falls back to a copy on Windows. SRM also creates `<shortId>.json` with a default BottomLeft position for a shortcut logo when position metadata is absent, preserving existing positioning. Validate whether the alias and layout file are needed on the supported Steam build before depending on them. [SRM artwork suffix map](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/artwork-types/available-artwork-types.ts) · [SRM grid writer and logo sizing](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-screenshots-file.ts#L16-L41) · [SRM alias writer](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-screenshots-file.ts#L277-L351) · [SRM shortcut icon handling](https://github.com/SteamGridDB/steam-rom-manager/blob/a02608984941eea9361afbc4a7b1fe2a162845e8/src/lib/vdf-manager.ts#L394-L441)

The SteamGridDB organization’s pinned API wrapper confirms HTTPS base `https://www.steamgriddb.com/api/v2`, `Authorization: Bearer <key>`, `GET /search/autocomplete/<encoded-title>` and `GET /games/steam/<real-appid>`. After resolving the game, use `GET /{grids,heroes,logos,icons}/game/<sgdb-game-id>`. These endpoints also accept service-specific identity types where supported. The wrapper exposes filters such as `dimensions`, `styles`, `mimes`, `types`, `nsfw`, `humor` and `epilepsy`. Grids cover both orientations. SRM exposes 600×900 portrait, 460×215 and 920×430 landscape and 1920×620 or 3840×1240 hero dimensions among its choices. Search and image results expose separate game and image IDs, thumbnail and full URLs, scoring and available author data. The official API UI did not render text through the research tool, so the wrapper is the endpoint and authorization evidence. API rate quotas and terms for redistribution were not verified. ## Windows write primitives

Microsoft documents `ReplaceFileW` for replacing an existing file with an optional original backup on the same volume. Its `REPLACEFILE_WRITE_THROUGH` flag is unsupported and a failed replacement can leave path/backup states that depend on the error. Flush staged bytes using `FlushFileBuffers`, verify file hashes after each transition, and use a journal to recover sets of files. Renaming one file does not make the set atomic. Ensure every target carries the intended sharing mode and report locks and access failures explicitly. [Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) · [Microsoft flushing](https://learn.microsoft.com/en-us/windows/win32/fileio/flushing-system-buffered-i-o-data-to-disk)
