# Store integration research

Source review as of November 21, 2026. **Code** describes behavior in the pinned revisions. **Documented** describes a vendor or tool contract. **Unresolved** means the source does not settle live availability, completeness, or support. No signed-in account, launcher action, or Steam data was used for this review.

## Epic Games Store

- **Code — account and inventory.** Playnite uses a browser sign-in with an alternate code route, validates or refreshes saved session data, and follows cursors in the library-items service. Inventory then joins each record to a catalog item using namespace and catalog item ID. `appName` is the library/install key used by this plugin, and the artifact ID is the local key used by newer launcher layouts. Preserve the other IDs as typed aliases. The same record can be eligible for import while requiring EA or Ubisoft for delivery. The plugin excludes private and Unreal records, requires an application category, filters digital extras and plugins, and keeps launchable add-ons where indicated. Catalog title, categories, launchable add-on and parent hints, and playtime are separate observations. Catalog cache is keyed by namespace, catalog item and build. Playtime or catalog failures can abort account import while the independently collected local list can survive. [EpicAccountClient](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/Services/EpicAccountClient.cs#L89), [EpicLibrary.GetLibraryGames and GetGames](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicLibrary.cs#L184), [metadata provider](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicMetadataProvider.cs).
- **Code — installed and actions.** Playnite branches on launcher v2, reading `installations.jsonl` and `catalog-cache.json` and checking completion, directory and `.egstore` manifest. The alternate EOS InstallHelper layout uses installed `.egi` entries with `catcache.bin` metadata. Legacy uses `.item` manifests and `LauncherInstalled.dat` for path reconciliation. The launch URI targets namespace, catalog item and app/artifact ID. Launcher v2 controllers attempt per-title install/uninstall protocol handoffs. Legacy controllers open the launcher library and observe install state afterward. Missing/corrupt local metadata, duplicate records and stale directories affect discovery. [EpicLauncherV2](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicLauncherV2.cs#L33), [EpicLauncher](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicLauncher.cs#L104), [EpicLibrary.GetInstalledGames](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicLibrary.cs#L38), [GetPlayActions](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicLibrary.cs#L353), [controllers](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/EpicLibrary/EpicGameController.cs).
- **Documented and unresolved.** Epic's publisher-facing Ecom docs distinguish durable ownership from consumable entitlements in an SDK sandbox. They do not establish a supported consumer-library API for Sync2Steam. The launcher services and URI behaviors above are implementation evidence. Catalog assets, library records, and purchase types can differ. The source does not establish whether every bundle component, free claim, subscription, trial, or externally fulfilled title is present or distinguishable. Import access as unknown when the upstream cannot establish its type. [Epic Ecom overview](https://dev.epicgames.com/docs/epic-games-store/services/ecom/ecom-overview).
- **Recommendation.** Ship local read-only discovery first. For optional account inventory test explicitly configured Legendary and Heroic integrations with a known tool version and a fictional JSON fixture before considering a native online adapter. Carry launchable add-ons as their own records with a parent, and hide engine and non-playable extras from shortcut suggestions by default.

## GOG

- **Code — account and inventory.** Playnite signs in using a visible web view and checks the session through an off-screen view. `GetOwnedGames()` starts with filtered account products (`hiddenFlag=0`, game media), walks pages, and preserves the numeric product ID as a string. The profile stats endpoint is separate and can fall back to the products endpoint. Stats failure can leave ownership data intact. Extras are opt-in and synthetic, with the base product and extra ID in the key. Product metadata lookup is separate and can fall back to exact title search for display data. A search result cannot establish ownership or identity. [GogAccountClient](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/GogLibrary/Services/GogAccountClient.cs#L22), [GogLibrary inventory and extras](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/GogLibrary/GogLibrary.cs#L354), [GOGMetadataProvider](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/GogLibrary/GOGMetadataProvider.cs#L34).
- **Code — installed and actions.** Playnite recognizes GOG uninstall registry entries, including standalone offline-installer installs, then validates primary tasks and root product ID from `goggame-*.info`. Current code also looks at `InstalledBaseProducts` and `LimitedDetails` in the Galaxy SQLite database opened read-only. It can launch the local primary task or hand off to Galaxy with product ID and install path. Install can be an account-page or Galaxy product handoff, or an opt-in Galaxy install command with readiness checks. Uninstall hands off to the local uninstaller. [GogLibrary actions and discovery](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/GogLibrary/GogLibrary.cs#L72), [registry and Galaxy database](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/GogLibrary/GogLibrary.cs#L222), [GogGameController](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/GogLibrary/GogGameController.cs#L57).
- **Unresolved.** Account filtering, joined DLC, hidden items, delisted products, old installer variants, Galaxy API availability and changing database columns need representative fixtures and live opt-in testing. A DRM-free executable proves a local launch candidate. Account access needs independent evidence. Keep extras and DLC related to their parent, keep installability independent, and allow the local result to remain usable offline.
- **Recommendation.** Start with registry and local product manifests. Add Galaxy database fallback once a fixture establishes both paths and lock handling. For account inventory prototype an opt-in Heroic snapshot with separate provenance. Avoid a required embedded WebView or a dependency on another tool's saved sign-in state.

## Xbox PC and Microsoft Store

- **Code — account scope.** Playnite performs interactive Microsoft OAuth, exchanges Xbox Live user and XSTS tokens, and fetches Xbox title history with optional batched playtime. PC import filters title-history records with a package family name (PFN), `Game` type and a `PC` device marker. Console-only history can be imported separately under synthetic keys built from title ID and media item type. Title history answers what the profile has played or recorded. It cannot prove purchase, current Game Pass access, or an unplayed owned title. The account settings gate the whole plugin, including local detection, and a non-success title-history status can become an authentication error in the source. Preserve auth, network and service failures separately in Sync2Steam. [XboxAccountClient login](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/XboxLibrary/Services/XboxAccountClient.cs#L38), [title history and stats](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/XboxLibrary/Services/XboxAccountClient.cs#L252), [XboxLibrary.GetGames](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/XboxLibrary/XboxLibrary.cs#L173).
- **Code — installed, metadata and actions.** Playnite correlates local UWP enumeration to the PFN-like app ID, using cached title data or a title-detail lookup for games without prior history. Detail can supply name, devices, date, publisher and developer. A fresh install without cached title classification can be missed during a connectivity failure. Its play controller re-resolves the packaged program at invocation. Install hands off to the Xbox app or a Store page keyed by PFN. Uninstall opens Windows Apps settings. Console records have no PC controllers. [XboxLibrary metadata](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/XboxLibrary/XboxLibrary.cs#L45), [XboxLibrary controllers](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/XboxLibrary/XboxLibrary.cs#L344), [XboxGameController](https://codeberg.org/CrowIsTaken/PlayniteExtensions/src/commit/67e4e398dd529774ddde7478c07b328c05e03caa/source/Libraries/XboxLibrary/XboxGameController.cs#L33).
- **Documented.** A PFN identifies a package family. An AUMID identifies an application within that package and is accepted by the Windows activation API for packaged apps in the current session. Keep these apart from Store product IDs, title IDs, and install paths. `Get-StartApps` is useful for installed launch candidates and only covers apps represented in Start. Microsoft GDK entitled-products APIs are documented in the context of a title and its related products. Microsoft describes direct purchases, bundles/subscriptions, and shared access separately. This does not establish a general consumer-inventory integration for Sync2Steam. [Package identity](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/package-identity-overview), [Finding AUMIDs](https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid), [Application activation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication), [GDK access to content](https://learn.microsoft.com/en-us/gaming/gdk/docs/store/commerce/fundamentals/xstore-granting-access-to-content), [GDK entitled-products scope](https://learn.microsoft.com/en-us/gaming/gdk/docs/reference/system/xstore/functions/xstorequeryentitledproductsasync).
- **Unresolved and recommendation.** Ship local current-user packaged discovery with an opt-in manual picker for ambiguous packages and multiple app entries. Include the AUMID-based activation route as a launch candidate and prove packaged Win32/GDK and UWP cases independently. Leave entitlement, subscription catalog and cloud access deferred until a supported source and realistic fixtures establish scope. Catalog availability, a subscription grant, and installed state are separate observations. Native Xbox/Store account IDs add no value to an installed-only path.

## Shared interpretation

Keep discovery, account access and metadata as independent snapshots with their own freshness, provenance and failure status. Bind the account input to an explicit profile. A complete successful refresh can reconcile missing records within its documented scope. A stale, partial, disconnected or failed refresh retains last known records and reports the limitation. Model base games, DLC, launchable add-ons, demos, extras, editions and bundles independently from purchase, claim, subscription, trial, sharing and observed history. One title can carry several observations. A bundle needs verified component relationships before affecting a component's access. Ask a driver for a typed action for a specific product/install record and revalidate at invocation. Checkout, acquisition, DRM or entitlement handling remains with the upstream client. See the [store contribution guide](../../docs/contributing/adding-a-store.md).
