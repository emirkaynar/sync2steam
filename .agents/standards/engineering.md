# Engineering, security and validation

## Rust and asynchronous work

Newtype StoreProductId, AccountKey, SteamAppId32, ShortcutGameId64, GroupId and ProfileKey at adapter boundaries. Preserve opaque IDs exactly; represent numeric display conversions explicitly. Define domain errors for unsupported, stale, expired auth, invalid data, conflict, unavailable and retryable I/O. Report operation and safe context. Reserve panics for broken internal invariants in tests. Never unwrap external data or skip a failed page. Keep provider DTOs private. Avoid a trait per function; substitute the clock, file root, HTTP, credential store and launch executor where behavior crosses boundaries.

UI work reads snapshots and submits cancellable jobs. Use bounded work queues with a revision to reject stale results; limit concurrent network calls per origin, decoded image bytes and filesystem jobs. Avoid holding a mutex across await. Run synchronous SQLite, image decode and VDF IO off the UI thread. Dispatch checks one game's state, never starts the library UI or enumerates every account. No periodic idle scans or autostart. Keep unsafe in narrowly scoped Windows wrappers with documented handle lifetimes, caller invariants and tests.

## Threat boundaries

- Use the system browser with provider-supported native authorization, PKCE and state where available. Bind a loopback callback to loopback only on an ephemeral port and validate redirect, state, expiry and intended issuer. Only use device code when issued for our registered client. No custom password form, embedded confidential client secret, cookie scraping or importing another program's refresh token. Missing sanctioned access means offer the supported local capability. [Native apps guidance](https://www.rfc-editor.org/rfc/rfc8252)
- Keep secrets in the user's credential set, namespaced to application + store + account. Revoke where supported, delete locally and invalidate in-flight refresh on disconnect. Refresh tokens serially per account; handle rotated-token write failure with reconnect. Credential Manager operates within the user's security boundary. Portable mode must never export secrets. [CredWriteW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew) · [CredDeleteW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-creddeletew)
- Build actions from validated typed IDs. Resolve executable against known launcher locations and validate an absolute path, then use an argument vector. Treat registered URI schemes as handoffs to user-configured software. Allowlist scheme, host and action per connector and encode components. Deny shell strings, arbitrary schemes, scripts, executable downloads and elevation. Show unknown handler or unavailable launcher explicitly.
- Validate content type, decode signatures and pixel/frame counts, HTTP size limits and redirects before saving images. Drop authorization on origin change. Never derive disk paths from a title or provider filename. Deny traversal, UNC/device paths outside explicitly supported roots, junction/reparse-point escapes and symlink substitutions. Revalidate file identity at commit. Reject unsafe target volumes if required write semantics cannot be established.
- Run as standard user. Limit DB, cache, logs and backups to that user. Log error codes, counts, durations and operation IDs locally. Redact identifiers/paths by default and exclude headers, cookies, query strings, launch arguments and raw response bodies. No automatic telemetry. Let users inspect diagnostic exports before sharing. Inventory only allowlisted local inputs; never inspect Steam authentication material.

## Test environments

Normal CI uses a synthetic directory root and in-memory credentials, offline mock transports and a recording launch executor. Tests must require an explicit disposable root; disable registry/process auto-discovery in fixture mode. Reject a root that resolves into a live Steam tree. No HTTP escape from mocked tests. Use fabricated account IDs and art. Explicitly opted-in client compatibility tests run in a disposable Windows user/VM with a dedicated test profile, beyond normal CI. Document client/launcher/OS builds, locale, DPI and evidence.

| Layer | Checks and regression oracle |
|---|---|
| Pure domain | Table-driven duplicate cases, sort order permutations, override undo, repeated plan/apply. Generate bounded identifier/path inputs. Assert invariants on every result. [Fixtures](../testing/duplicate-fixtures.md) |
| Steam adapter | Golden binary and textual KeyValues, retained unknown supported fields, byte-preserved unrelated records, malformed/truncated types, nesting limits, duplicate keys, signed/unsigned AppIDs, Unicode and quoted paths, empty files vs absent files, multiple accounts/roots. Unsupported format stops all affected writes. Check repeated apply and ledger recovery. |
| File transaction | Inject access denied, file lock, disk full, restart at each journal transition, unexpected external edit, Steam restart between preview and apply. Verify old or verified new images per file, explicit conflict otherwise. Keep the backup restorable even if the database is missing. |
| Store adapters | Fixture variants by launcher version, expired token, changed account ID, refresh rotation, cursor loops, truncated pages, duplicate rows, pagination cancellation and offline local installations. Verify scoped evidence and exact typed launch/install intents. |
| Artwork/collections | Simulate art lookup mismatch, unsupported file and decode bomb, manual cover or collection edit since last write, Steam/cloud restart and conflict. Shortcut success survives optional-art failure. |
| UI and performance | Keyboard-only import and removal, focus after filter/dialog, partial inventories, bulk selection and preview, mixed DPI and localized text. Record foreground evidence and distributions on named hardware. [UI standards](ui.md) |
| Optional live checks | Record conclusions with dated versions, sanitized examples and explicit scopes. Use disposable credentials and fixtures obtained with consent. Never require contributor accounts to run ordinary tests. |

On dependency changes review Cargo.lock, license graph, advisories and enabled features using cargo-deny and RustSec cargo-audit. Pin tools in CI when implemented. Use rustfmt, Clippy and Windows MSVC CI to verify CLI/headless and UI entry points; Rust unit tests alone cannot verify format compatibility with Steam.
